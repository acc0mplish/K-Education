# Changelog

사용자에게 배포되는 BatiOffice 제품 변경을 기록한다. 버전 규칙과 정본은
[`docs/guides/versioning.md`](docs/guides/versioning.md)를 따른다.

쓰는 규칙 (0.8.0부터): **제목은 명사형 단답**(굵게), **설명은 높임말 한 문장으로
핵심만**. 배경·경위·사과는 여기가 아니라 커밋과 PR에 적는다. 제목은 업데이트 창에
그대로 나가고, 설명은 첫 항목의 것만 그 아래에 붙는다. 지난 항목은 당시 쓴
그대로 둔다 — 기록이기 때문이다.

## 0.9.8 — 2026-08-27

### Added

- **호출 단축키 선택** 설정 ▸ 일반에서 전역 호출 단축키를 네 가지 조합 중
  원하는 것으로 바꿀 수 있습니다.

### Improved

- **한글 편집기 엔진 업데이트** 중첩 표 배치와 특수 글자 표시, 여러 칸
  동시 서식이 정확해지고 큰 표가 빨라집니다. 파일 보안 방어도
  강화되었습니다.

- **호출 한 번에** 창이 닫혀 있어도 전역 단축키 한 번으로 창과 명령
  입력창이 함께 열립니다.

## 0.7.35 — 2026-08-21

> 이 버전부터 항목은 **제목(명사형) + 설명(높임말)** 으로 적는다. 제목은 업데이트
> 창에 그대로 나가고, 설명은 첫 항목의 것만 그 아래에 붙는다. 사용자가 읽는 문장이라
> 커밋 제목과 같은 이유로 형식을 고정한다.

### Fixed

- **로컬 AI 모델 첫 질문 시간 초과 수정** Ollama는 모델을 메모리에 다 올린 뒤에야
  응답을 시작하는데, 앱이 그 대기를 네트워크 지연으로 보고 1분 만에 끊고 있었습니다.
  이제 로컬 모델에는 로딩에 필요한 시간을 드립니다.
- **로컬 모델 유지 시간 연장** 몇 분 쉬었다 다시 물으면 모델을 처음부터 다시 올리느라
  또 오래 기다리셔야 했습니다.
- **Ollama 상태 표시가 설정한 주소를 봅니다** 기본 포트가 아닌 곳에서 Ollama를 쓰시면
  AI는 정상인데 "실행 중이 아님" 으로 보였습니다.
- **추천 로컬 모델에 메모리 여유 반영** 그동안은 모델이 요구하는 최소치에 딱 맞춰
  추천해서, 16GB 기기에 16GB가 필요한 모델을 권했습니다. 운영체제와 BatiOffice가 쓰는
  몫이 빠져 있었습니다.

### Changed

- **업데이트 창에 주요 변경 강조** 항목을 똑같은 크기로 나열하니 읽기 어려웠습니다.
  가장 중요한 변경 하나를 앞세우고 나머지는 짧게 적습니다.
- **일반 업데이트는 조용히 설치됩니다** 그동안은 새 버전이 나올 때마다 창이 떠서
  작업을 끊었습니다. 이제 대부분의 업데이트는 백그라운드로 받아 두었다가 앱을 닫을 때
  설치되고, 꼭 알려야 하는 경우에만 창이 뜹니다.
- **AI 패널이 로그인 전에도 보입니다** 그동안은 패널을 열면 로그인 화면이 덮고 있어서
  무엇을 할 수 있는지 볼 수 없었습니다. 이제 예시 질문과 입력창을 먼저 보시고, 실제로

- 비공개 BatiOffice 소스 저장소와 공개 다운로드·업데이트 아티팩트 채널의 경계를 명문화했다.
  운영 배포는 서명된 버전 고정 바이너리와 업데이트 메타데이터만 Bati 소유 CDN에 게시하며,
  별도 공개 소스 저장소를 요구하지 않는다.
- Docs와 HWP 편집기 renderer를 문서 탭마다 무제한 생성하지 않고 편집기 종류별 최대 2개까지
  재사용하는 bounded pool로 전환했다.

### Fixed

- Docs/HWP 탭을 반복해서 열고 닫을 때 숨은 renderer와 이벤트 리스너가 누적되어 Electron 메모리가
  계속 증가하던 문제를 수정하고, crash·탭 종료·앱 종료 시 자원을 회수하도록 lifecycle을 강화했다.
- Docs/HWP 각각 30회 반복 open/close Electron E2E로 renderer 수가 제한되고 후반부 RSS 증가량이
  안정화되는 회귀 기준을 추가했다.

## 0.7.2 — 2026-08-15

### Changed

- Gemini BYOK의 새 설치 기본 모델을 빠르고 비용 효율적인 `gemini-3.5-flash-lite`로 변경했다.
- Sheets의 시작 질문을 빈 시트에서는 샘플 데이터·수식·차트 생성 중심으로, 데이터가 있는 시트에서는
  요약·합계·수식 검사 중심으로 일관되게 제공하도록 단일 정본으로 통합했다.
- 모델 카탈로그 capability, 서버 실행 게이트, 데스크톱 release gate와 provider adapter가 같은
  도구 지원 정책을 따르도록 모델별 tool runtime 경계를 문서화하고 검증했다.

### Fixed

- Sheets AI가 오른쪽 정렬을 적용할 때 편집기 facade가 지원하지 않는 `right` 값을 전달해 작업이
  중단되던 문제를 의미 보존형 `normal` 정렬로 변환하도록 수정했다.
- 저장 전 셀 변경이 시트 범위 계산에서 빠져 요약·분석 도구가 빈 시트로 오인하던 문제를 수정했다.
- 같은 도구와 같은 인자가 반복 실패할 때 전체 턴 한도까지 재시도하던 동작을 3회에서 중단하고
  변경을 롤백하도록 공통 에이전트 루프를 강화했다.
- Ollama 응답의 분할된 추론 태그를 사용자 메시지에서 제거하고, Qwen 계열에는 비추론 모드를
  명시하며, 도구 미지원 응답을 편집 성공으로 조용히 오인하지 않도록 구조화된 오류로 승격했다.

## 0.7.1 — 2026-08-15

### Fixed

- ARM64 서명·공증 릴리스가 불필요한 Intel Rust 타깃을 요구하지 않도록 아키텍처별 패키징 경로를
  분리하고, universal sidecar는 명시적인 dual-architecture 명령에서만 만들도록 수정했다.
- 빈 Sheets에서 샘플·데모 데이터를 생성할 때 존재하지 않는 범위를 먼저 읽거나 동일한 잘못된
  변경안을 반복하지 않도록, 데이터 작성·적용·재읽기와 수식·서식·차트 적용을 두 단계로 나눴다.
- managed AI가 분류되지 않은 `unknown` terminal 오류를 반환할 때 내부 문구를 그대로 노출하지
  않고, 재시도 가능 여부와 복합 작업 분할 방법을 안내하도록 개선했다.

## 0.7.0 — 2026-08-15

### Changed

- GenOffice upstream과 독립된 BatiOffice `0.7.x` 제품 버전선을 시작했다.

  BatiOffice 홈에서 만든 빈 XLSX도 매출 샘플·예산 차트·프로젝트 일정처럼 생성 효용을 보여주는
  starter 질문을 표시하고, 실제 값·수식·리치 텍스트·구조가 있는 파일은 분석 질문을 유지한다.

## 0.6.2 — 2026-08-12

- Sheets와 HWP의 빈 문서 AI 패널에 편집기별 샘플 질문을 추가하고, Docs·Slides·Markdown과
